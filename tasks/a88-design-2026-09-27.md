## 1. 土台の修理（全員に効く）

**方針: 2 本のコンテンツブロッカーに役割を分け、捨てているルールを 2 本目に載せる。基本保護は「2 本目が無効な人でも今より悪くならない」ことを必須条件にする。**

- 基本保護（全員）= セキュリティ（オン時 3 万件）＋ 優先順に選んだ広告ルール（残り枠）。★セキュリティを先に確保する＝今 0 件の詐欺サイト対策を戻す
- 報告反映（2 本目）= ポップアップ 40 件 ＋ 判定済みの報告ルール ＋ 基本保護に入り切らなかった広告ルール
- 例外ルールは同じブロッカーの中でしか効かない。★**例外（重複除き 9,005 本）は 2 本の両方の末尾に入れる**（C3）＝上限なしの 1 本のリストと同じ効き方になる。リスト単位で分けるだけ（C1）だと、例外と遮断が別のブロッカーに分かれた分が効かない（ニコニコの ima3.js・TVer の posall は C1 でも止まったまま・C3 で通る。無関係なサイトでは C3 でも止まる）。件数は基本保護 138,428・2 本目 129,468（ポップアップ・報告ルール込み）で両方 15 万未満・WebKit コンパイル成功。**分け方は計測で決める**（候補: ①リスト単位〈基本保護 = 日本語 + base + セキュリティ／2 本目 = easyprivacy + easylist〉②今の順番のまま前後で切る ③日本のサイトに当たるルールを優先して選ぶ）

## 2. 報告の週 1 回判定

- **下ごしらえは Claude なしで毎週自動**（launchd・Mac 上）: 新しい報告を D1 から読む（読み取りのみ）→ 1 の計測の道具で報告ページを今の規則で開き、漏れている広告の通信・残っている広告らしき要素・画面を集めて「判定用の束」を作る → 朝のレポートに「未判定 N 件」を出す
- **判定は次に開いたセッションで Claude が行う**（SessionStart で未判定があることを知らせる）。★Claude を定期的に自動起動する形（利用枠を使う）は黙って入れない＝入れるなら kureho の承認を取る
- 判定の結果は**リポジトリのファイル**に書く: そのサイト限定のルール（`if-domain`＝報告されたサイト）と、報告ごとの結果（反映した／アプリ内広告で Safari では消せない／サイト自身が出す広告で消せない／再現しない／無効な報告）。ルールは既存の週次配信で 2 本目に載る。報告ごとの結果は GitHub Actions が D1 に書き込む（既存のスクリプトと同じ経路・本番 DB を手で触らない）
- 止まっている `kureho_queue` と 14 日を過ぎた `pending` も、この判定の対象に入れる（出口を作る）
- ★**判定は新しい報告の全件に結果を書く**（自動の関門で反映された分も含む）。理由: `reports.status` は集計後 `aggregated` で止まり、反映・却下は `rule_candidates` 側にしか残らない（`applied_at` も書かれない）＝結果 API は `review_outcome` が無い報告を「確認中」としか返せない。結果 API = main 35ab23e（migration 0015・`POST /v1/reports/status`・`.github/workflows/apply-review-results.yml`）。**9/27 本番反映済み**: 本番 DB に 0015 適用（列 2 つを読み取りで確認）→ Version 3821202d-703d-4b4e-8665-8f264dfa237c → 本番で 405/400/200 を確認 → Actions は push 起動・dry_run 起動とも成功（結果ファイル 0 件で何もしない）
- 自動の関門（14 日・3 人・2 回線）は残す＝人が見る前に自動で入る道として。1 件からの反映は人の判定を通したものだけ
