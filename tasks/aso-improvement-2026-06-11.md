## 2. 次バージョン（v3.0.3 / v3.1）提出時に反映

### keywords（現状 → 改善案）

現状: `広告,消す,ブロック,うざい,詐欺,フィッシング,セキュリティ,学習,報告,進化`

問題: **10 語中 6 語が name/subtitle と重複**（広告・消す・ブロック・学習・報告・進化は indexed 済みで二重投資）。

改善案（90 字 / 上限 100・重複ゼロ）:

```
アドブロック,adblock,コンテンツブロッカー,詐欺,フィッシング,セキュリティ,ポップアップ,バナー,追跡,トラッカー,プライバシー,通信量,節約,軽量,うざい,迷惑
```

- 「アドブロック」「adblock」「コンテンツブロッカー」が現状完全に未カバー（このカテゴリの主要検索語）
- 5.2.5: Safari は入れない（v2 提出時の reject 実績あり）

### name / subtitle

現状維持を推奨: `学習する広告消し - 消えない広告もブロック` / `他で消えない広告も、報告で進化`
（v3.0 ローンチ直後で差別化軸が固まっており、頻繁な変更は検索ランキングの蓄積をリセットするリスク）

### description

冒頭は現状の「他のブロックアプリで消えない広告が残るとき」で OK。
中盤に「標準フィルタの実数（15万ルール / EasyList / AdGuard / URLhaus / Phishing.Database）」の数字ブロックを追加検討（CVR 向け・indexed ではない）。

## 3. 戦略論点（kureho 判断事項・実行はしない）

実数が示す構造問題: **¥700 前払い × 露出ゼロ × 飽和カテゴリ**。

- 有料前払いはストアの検索・ブラウズアルゴリズム上 DL 母数が伸びにくく、レビューも溜まらない（現状レビュー数 = 購入者のみ）
- 選択肢として「無料 DL + 買い切り IAP アンロック」へのモデル変更があり得る（StillCam で実証済みの構造）。ただし大工事（機能ゲート実装 + 既存購入者の grandfather 処理）なので、ASO 改善の効果を 2〜4 週見てから判断で十分
- LP の SEO 流入もゼロなので、app-support LP の記事コンテンツ追加（「広告 消えない」系の検索意図）は中期候補

## 4. 実行順序

1. ✅ データ取得・診断（本文書）
