# 広告消し: 詐欺サイト対策を看板にし、アプリ内のリンクも止める 設計書

作成: 2026-11-09 / 状態: **kureho 承認済み（2026-11-09・選ぶ窓「このまま進める」）**／台帳 A-218
根拠の調査: `AdblockKeshi/tasks/security-positioning-research-2026-11-09.md`（数字・出典・ACH・反論はそちらが正）

---

## 1. 目的と理由

- kureho（2026-11-09）「直近情報流出やAIによるサイバー犯罪が増えてて、それが不安な人に刺さるエンハンスとかうまくできないかな？」
- 今の広告消しの詰まりは「見つけてもらえない」こと（App Store の表示 1 日 20〜50 回・新規 DL 1 日 0〜3 件・10 月の売上 3,148 円）
- 詐欺サイト対策は v2.0 から入っているが、ストアの名前・副題は広告消しだけで、詐欺対策はキーワード欄に埋もれている
- 調査で見えた空き: 詐欺対策を売るアプリは全部月額か年額（280blocker の詐欺対策プラン 月 ¥300、ウイルスバスター 月 ¥360〜 ほか）。**買い切りで詐欺サイトを止めるアプリは見た範囲で無い**。Safari には標準の詐欺警告があるので、差が出るのは **Safari の外**（LINE・メール等のアプリ内で開くリンク）
- 需要の裏づけ: フィッシング報告は 2025 年に約 245 万件で過去最多。詐欺 SMS のリンクを押した人 12.7%→14.2%、お金の被害 5.3%→6.0%

## 2. kureho が決めたこと（2026-11-09・選ぶ窓）

1. 看板（ストアでの見え方）と機能の**両方**を変える。**看板が先**
2. 届ける相手 = **自分のスマホを自分で守りたい、スマホに慣れた人**（20〜40 代を想定）
3. 足す機能 = **他のアプリ内（LINE・メール等）で開いたリンクも、詐欺サイトなら自動で止める**。今の買い切り「アプリ内広告ブロック」に入れる（無料の人は Safari の詐欺対策まで）

## 3. 7 月の「不採用」との関係

- 2026-07-14 の v4 設計（`docs/superpowers/specs/2026-07-14-v4-freemium-dns-design.md` §2）で「詐欺特化再ポジショニング」は不採用。理由（`~/claude/tasks/dl-uplift-plan-2026-07.md` 調査D）: ソフトバンク系「みやブル」が 12 年で ★2.9・1,034 件＝需要が薄い可能性／Safari の静的な規則で「検知」を名乗ると 2.3.1 でアカウント停止の危険（全アプリが人質）
- 今回の違い: ①詐欺に「特化」せず、広告消しと並べる 2 枚看板 ②2025 年の過去最多・被害率の上昇という新しいデータ ③Safari の外で止める中身（DNS）がある
- 2.3.1 の危険は §7 の文言の決まりで守る。§2 の選択は、どれも 7 月の不採用を kureho に伝える前に行われた（1・2 は一覧の偏り〈§6-1〉を伝える前でもある）。この設計書の承認をもって、経緯を承知の上での判断とする

## 4. 目標・非目標・反目標

### 目標
- **G0** 詐欺サイトの一覧の選び方を直す（今は 30,000 件のうち 29,602 件が数字で始まるドメインに偏っている・§6-1）
- **G1** 看板の第 1 弾: 名前・副題・キーワード・説明文・宣伝文・掲載画像・サポートサイトを、詐欺サイト対策を前に、広告消しを並べる形にする。言うのは今ある機能の範囲だけ
- **G2** 買い切りの「アプリ内広告ブロック」に詐欺ドメインを足し、他のアプリ内で開いたリンクも止める
- **G3** 看板の第 2 弾: G2 の配信と実機確認の後に、「他のアプリで開いたリンクも（買い切り）」を足す
- 見る指標: App Store の表示回数・新規 DL・購入（apps-metrics-dashboard）。G1 の配信前 4 週と後 4 週で比べる

### 非目標（今回やらない）
- SMS の迷惑・詐欺フィルタ（iOS 26 標準と重なる・日本での動きが不明）
- 迷惑電話の判定
- メールアドレス・パスワードの流出確認（HIBP）
- 共有メニューで「開く前にリンクを確かめる」（次の候補として残す）
- iOS 26 の URL Filter 方式・自前の DoH サーバー（7 月に不採用・運用費）
- Google Web Risk API など新しい有料サービス（使うなら kureho の事前承認）
- サブスク
- ブロック件数・履歴の表示、通知（案件の「やらないこと」のまま）

### 反目標（技術的に動いても、こうなったら失敗）
- 不安をあおる見せ方（警告色だらけの画面・脅し文句）
- やっていない事を言う（ウイルス対策・検知・AI で判定・すべて防ぐ・安全を保証）→ 2.3.1
- 説明文と実物がずれる（無料と買い切りの境界、どのスイッチ・どの Safari 拡張をオンにすれば効くか）＝A-162 と同じ種類の誤り
- 銀行・決済・公的機関など必要なサイトを誤って止める
- 端末の外へ新しいデータを送る（「判定は端末内」の約束を壊す）
- 今ストアで「広告を消したい」と探してくれている人を手放す

## 5. 制約

- **Safari の規則**: 1 本 15 万件まで。詐欺の枠は 2 本目（報告反映）の末尾 30,000 件固定（A-88 の設計）。基本保護には詐欺の規則はほぼ入っていない
- **DNS（アプリ内広告ブロック）**: `Shared/DNS/DNSBlocklist.swift` の上限 200,000 件。Network Extension のメモリ上限は目安 約 50MB で未実測。今の DNS の広告一覧は手で選んだ 61 件（同梱と配信が同じ・2026-07-15 から未更新）
- **元の一覧**: Phishing.Database ACTIVE 392,178 件（MIT・ほぼ名前順）＋URLhaus（CC0）。Tranco 上位は誤ブロック避けで除外。重要ドメイン約 50 は止めない（`CriticalDomainGuard`・`DNSCriticalGuard`）
- **配信**: GitHub Pages。週次の自動更新で、**旧版の利用者にもアプリの更新なしですぐ届く**。配信物を変える前に計測し、kureho の承認を取る。GitHub Actions のワークフローを変える時は kureho の明示承認と `timeout-minutes`
- **審査**: 2.3.1(a)（誤解を招く宣伝・ウイルススキャナを例示）／2.3.7（名前・副題・キーワードに価格や他社の商標を入れない。memory `feedback_pricing_metadata_strict`）／5.4（DNS は 4.0〜4.4.3 で審査を通っている）
- **名前を変えると**検索順位の蓄積が動く可能性がある（7 月に「広告ブロック」99→44 位の記録）
- **実装**はこのアプリ単体を開いたタブで行う。審査提出・本番の配信は kureho の承認

## 6. 何を作るか

### 6-1. G0 詐欺サイトの一覧の選び方
- 事実（2026-11-09 測定）: 規則 30,000 件のうち数字始まり 29,602・英字始まり 398。原因は `scripts/build_security_rules.py` の `build_security_rules()` が元の並び順のまま 30,000 件で打ち切ること。`amazon` を含む詐欺ドメインは元の一覧に 3,694 件、今の一覧には約 120 件。配信中の `docs/cdn/second-ads-sec.json` もアプリ同梱の `Extension/Resources/security-rules.json` も同じ偏り
- 方針: 並び順で切らない。**日本向けを優先**（日本のブランド名・`.jp`・日本の利用者を狙う偽装の形）し、残りは偏らない選び方で埋める。URLhaus は残す
- 元の一覧はホスト名の一覧（パスは無い）。共有ホスティングの**親ドメインそのもの**（`github.io`・`blogspot.com`・`weebly.com`・`000webhostapp.com` など）は入れない（その下の個別のサブドメインは入れてよい）。Safari 用と DNS 用は同じ元データから別々に選び、計測も別々に出す
- 確かめ方: 直す前と後で ①日本向けの最近の詐欺ドメインの見本（協議会の注意喚起などに載った物）を何割止められるか ②Tranco 上位・重要ドメインの誤ブロック 0 ③WebKit が読めること（コンパイル成功）④旧版でも読める形式・件数
- **配信の前に kureho へ数字を見せて承認を取る**

### 6-2. G1 看板の第 1 弾（今ある機能の範囲で言う）
- 名前に「広告消し」を残し、「詐欺サイト」を入れる。副題で「詐欺サイトも広告も止める」を、本体ブラウザの範囲で言う
- 説明文の冒頭を詐欺サイト対策にする。「無料でできること」「買い切りでできること」を 1 行ずつ書く。本体ブラウザの詐欺対策がどの拡張（今は報告反映）をオンにした時に効くかを、実物どおりに書く。報告反映は無料（v4 設計 r2 で無料のまま維持）なので、本体ブラウザの詐欺対策は無料の人も報告反映をオンにすれば効く
- **G0 の配信が済んでから G1 を出す**（偏った旧一覧のまま「詐欺サイト対策」を看板にしない）
- 無料の人の実際の動き（報告反映をオンにした時に Safari の詐欺対策が効くこと・案内の画面がそこへ導くこと）を、提出前に実機で確かめてから文言を確定する。説明文と実物の照合は、今までの提出前の照合表（`tasks/release-*-consistency.md` の形）で行う。案内が報告反映へ導いていなければ、G1 の版で案内を直す
- 掲載画像の 1 枚目を詐欺サイト対策にする。**作った物を kureho に見せ、レビューを通るまで採用しない**
- サポートサイト（app-support `src/lib/products.ts` の広告消しの節）も同じ内容に
- 宣伝文（審査なしで変えられる）も同じ方向に
- 叩き台（最終は画像と一緒に kureho のレビューで決める）:
  - 名前: 「広告消し - 詐欺サイト・広告ブロック」
  - 副題（第 1 弾）: 「詐欺サイトも広告も、開く前に止める」
  - 副題（第 2 弾・G3）: 「アプリ内の詐欺リンクも止める」の方向
  - ★掲載情報（名前・副題・キーワード・宣伝文・説明文）に **Safari・iPhone・Apple を書かない**（5.2.5・v2 提出時に却下の実績・`tasks/aso-improvement-2026-06-11.md`）。今の説明文と同じく「本体ブラウザ」と書く。LINE などの他社名も名前・副題・キーワードには入れない（説明文で書けるかは 5.2.5 の範囲を確かめてから）

### 6-3. G2 アプリ内広告ブロックに詐欺ドメインを足す
- 対象: 買い切りの人だけ（今の DNS と同じ判定）
- 一覧: G0 と同じ元の一覧から DNS 用に選ぶ。件数はメモリの実測で決める。週次で更新する（今の DNS の更新の仕組み `DNSListUpdater` に配信ファイルを足す）
- 重要ドメインは止めない（`DNSCriticalGuard`）
- 止めた時の見え方: **何も出さない（ページが開かないだけ）**＝案件の「やらないこと」のまま。止めたことを見せる表示を作るのは、kureho が「やらないこと」の例外を承認した時だけ
- 誤ブロックへの備え（DNS は端末全体の名前解決に効き、決済・銀行・配送通知のリンクを誤って止めた時の害が広告より大きいため）: Safari 用より厳しく選ぶ（Tranco 除外を広めに取る・重要ドメインの守りを銀行・決済・配送・公的機関まで確かめる）。逃げ道は今ある一時停止（15 分・1 時間）と「サイトが壊れた」報告。DNS 用の「このサイトで一時オフ」は今回は作らない（誤ブロックの報告が来たら次の候補）
- オン・オフ: メイン画面の「詐欺サイトブロック」のスイッチに従う（オフなら DNS でも詐欺は止めない）。一時停止（15 分・1 時間）は広告と同じく効く
- 判定は端末内。新しく外へ送るデータは無い
- 確かめ方: 試験（一覧の読み込み・判定・重要ドメイン・スイッチ・上限）と、**実機で LINE とメールのアプリ内ブラウザから止まることの確認**。止まらないアプリがあれば G3 の言葉からそのアプリを外す

### 6-4. G3 看板の第 2 弾
- G2 の配信と実機確認の後: 副題・説明文・掲載画像・サポートサイトに「他のアプリで開いたリンクも止める（買い切り）」を足す。§7 の決まりに従う

## 7. 文言の決まり（全段共通）

- 言ってよい: 「既知の詐欺サイト・フィッシングサイトの一覧と照らして止める」「詐欺サイトをブロック」「判定は端末内」「サブスクなし（説明文で）」
- 言わない: ウイルス対策・ウイルススキャン・検知・AI で判定・すべて防ぐ・100%・安全を保証・情報漏えいを防ぐ
- 書かない語: Safari・iPhone・Apple（5.2.5）、価格（2.3.7）
- 必ず添える: 新しい詐欺サイトは、一覧に載るまで止められないことがある
- 無料と買い切りの境界を説明文で明記する

## 8. 順番

1. **G0**（アプリの版は要らない・配信の前に kureho の承認）
2. **G1**（G0 の配信後の次のアプリの版: 掲載情報と画像、同梱の一覧の差し替え）
3. **G2**（アプリの版＋配信ファイル＋ワークフローの変更）
4. **G3**（G2 の版と同時か直後）

- 承認: 本番に効く物（配信・ワークフロー・審査提出）は、それぞれが出せる状態になった時に kureho の承認を取る。同じ時に出る物（G2 の配信ファイルとワークフロー、G2 と G3 の提出など）は 1 回にまとめて見せてよい
- 名前を戻す基準: G1 の配信後 4 週で、表示回数が前の 4 週を下回り、かつ「広告ブロック」の順位が 20 位以上落ちたら、次の版で名前を元に戻す（副題とキーワードの詐欺の語は残す）

## 9. 作る人に任せること

- 一覧の選び方の細部（日本向けの見分け方、件数の配分、新しさの扱い）
- DNS の件数・データの持ち方・配信ファイルの形
- ワークフローの中身（承認を取る前提で）
- 名前・副題・説明文の最終の言葉（§7 の範囲で。最終は kureho のレビュー）
- 掲載画像の作り（最終は kureho のレビュー）
- 試験の計画

## 10. Claude が決めたこと（kureho が読む時に確かめてほしい物）

- 言葉の調子は、怖がらせず「何をどう止めるか」を具体的に言う
- 「AI 詐欺から守る」とはうたわない（公的な件数が無い）
- 名前に「広告消し」を残す（今の客と検索順位を守る）
- 新しい有料サービスは使わない（Web Risk 不使用）
- 止めた時の表示は作らない（「やらないこと」のまま）
- DNS の詐欺ブロックは「詐欺サイトブロック」のスイッチに従う
- G0 の一覧の直しを最初にやり、G0 の配信が済むまで G1 を出さない
- DNS の詐欺ブロックは Safari 用より厳しく選び、逃げ道は今ある一時停止と報告だけにする（DNS 用の「このサイトで一時オフ」は作らない）
- 共有ホスティングの親ドメインは一覧に入れない
- G1 の提出前に、無料の人の実際の動きを実機で確かめる
- 名前を戻す基準は「4 週で表示回数が下がり、かつ『広告ブロック』が 20 位以上落ちたら」
- 共有メニューでの確認・SMS・流出確認は今回やらない

## 11. 未確認（設計に効く物）

- LINE・メール等のアプリ内ブラウザで DNS が効くか（G2 の実機確認で決着）
- 直した一覧が日本向けの詐欺サイトをどれだけ拾えるか（G0 の計測で決着）
- Network Extension のメモリ上限（G2 の実測で決着）
- App Store での検索語の人気度（「詐欺サイト」「フィッシング」と「広告ブロック」の比較）
